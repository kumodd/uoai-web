## 1. Purpose

This document defines the **formal MVP Acceptance Checklist (MVP-AC-01 – MVP-AC-17)** and the **Verification Test Case Catalogue (TC-001 – TC-045)**.

**MVP Release Gate Rule:** The MVP cannot be approved for public release until **all 17 MVP Acceptance Criteria (MVP-AC-01 – MVP-AC-17)** pass on the primary supported reference configurations (RC-1, RC-2, RC-3; and RC-4 for negative capability/resource tests).

## 2. Formal MVP Acceptance Checklist

| ID | MVP Demonstration Item | Testable Acceptance Criteria (Pass / Fail Conditions) | Linked Requirements | Verification Test Cases |
|---|---|---|---|---|
| **MVP-AC-01** | **1. User installs the extension.** | - Extension installs cleanly in supported Chromium browsers (Manifest V3) with zero console or manifest errors.<br>- Required permissions match the least-privilege manifest specification (no `<all_urls>` required host permission).<br>- Default settings initialize in `chrome.storage.local`. | FR-001, FR-123, NFR-016, NFR-017, NFR-018 | TC-001 |
| **MVP-AC-02** | **2. User opens the UOAI dashboard.** | - On initial install, the Dashboard opens automatically to the Welcome screen within 3 s.<br>- User can reopen the Dashboard at any time via the extension toolbar popup or trusted PWA origin.<br>- All 7 primary screens navigate without error. | FR-001, FR-004, NFR-006, NFR-026 | TC-001, TC-042 |
| **MVP-AC-03** | **3. Browser capability checks run.** | - Browser API and WebGPU capability checks run automatically during onboarding and on demand.<br>- WebGPU detection runs inside the worker execution context and captures adapter limits and features.<br>- On an unsupported browser/GPU, 100% of runs display a plain-language explanation and disable downloads of incompatible models. | FR-002, FR-003, FR-012, BR-13 | TC-002, TC-019 |
| **MVP-AC-04** | **4. User downloads a supported model.** | - Catalog displays only qualified models with size, quantization, context length, license, and compatibility badge.<br>- License acceptance is enforced prior to download where required.<br>- Persistent storage is requested (`navigator.storage.persist()`) and free space is verified before download.<br>- Download displays live progress (bytes, %, rate, ETA) and supports pause/resume or recovery after interruption. | FR-006, FR-010 – FR-017, FR-048, FR-106, FR-108, BR-11, BR-19 | TC-003, TC-004, TC-005, TC-006, TC-013 |
| **MVP-AC-05** | **5. Model integrity is verified.** | - Every downloaded model artifact is hashed with streaming SHA-256 and compared against the verified registry manifest.<br>- If all hashes and byte sizes match, the model is atomically committed to local storage with status `Ready`.<br>- If any byte in any artifact is modified or truncated, verification fails, the corrupted file is deleted, and the model is never marked `Ready`. | FR-018, FR-019, FR-119, BR-08, NFR-008, NFR-009 | TC-007, TC-008, TC-013 |
| **MVP-AC-06** | **6. Model loads successfully.** | - A `Ready` model loads from local storage into a dedicated Web Worker with WebGPU acceleration (never in the MV3 Service Worker).<br>- Staged loading progress is displayed in the UI.<br>- Model transitions to `Loaded` / runtime status `ready` with zero network requests during load. | FR-007, FR-021, FR-040, FR-041, FR-047, NFR-005 | TC-009, TC-037, TC-038 |
| **MVP-AC-07** | **7. User generates a response locally.** | - Submitting a prompt in the Local AI Workspace formats the chat template, tokenizes locally, generates tokens via WebGPU, and streams incremental Markdown output to the UI.<br>- UI thread remains responsive (0 long tasks > 200 ms attributable to UOAI UI).<br>- Conversation and messages are saved in local IndexedDB. | FR-008, FR-030 – FR-033, FR-036, FR-042 – FR-045, NFR-001 – NFR-003 | TC-010, TC-039 |
| **MVP-AC-08** | **8. User disconnects from the internet.** | - Offline Readiness indicator shows `Offline Ready` once app assets, runtime WASM/JS, and at least one verified model are present.<br>- When OS network connectivity is disabled, UOAI detects offline state immediately, displays the offline badge, and disables online-only actions (new downloads, catalog refresh) with clear labels. | FR-005, FR-038, FR-100 – FR-103, NFR-013 | TC-015, TC-016, TC-018 |
| **MVP-AC-09** | **9. User can still reopen UOAI and generate a response.** | - With OS network connectivity disabled and after a full browser quit and restart, opening the Dashboard reaches an interactive state in ≤ 3 s on RC-1 – RC-3.<br>- Prior conversation history and installed models are available.<br>- User loads the installed model from local storage and completes a multi-turn streaming chat offline with 0 network failures. | FR-038, FR-101, FR-102, FR-104, FR-105, NFR-006, NFR-010, NFR-012 | TC-017, TC-018 |
| **MVP-AC-10** | **10. An authorized third-party website connects through the SDK.** | - User authorizes an HTTPS third-party origin via the two-layer consent flow (UOAI consent sheet + browser optional host permission).<br>- Content-Script Bridge is registered and injected only for the authorized origin.<br>- Calling `await UOAI.connect()` and `await ai.models.list()` from the website succeeds and returns the list of installed `Ready` models. | FR-060 – FR-063, FR-065, FR-067, FR-070 – FR-073, FR-077, FR-078, FR-080 | TC-021, TC-041 |
| **MVP-AC-11** | **11. The website receives a local inference response.** | - Authorized website calls `await ai.chat.completions.create({ model, messages })` (non-streaming).<br>- Provider validates schema, origin, rate limits, and queue limits, executes inference locally, and returns an OpenAI-compatible `ChatCompletion` object with `choices[0].message.content` and `usage`.<br>- Website request cannot read or modify the user's Workspace conversations. | FR-051, FR-066, FR-074, FR-116, FR-117, BR-07, BR-09, BR-10, BR-23 | TC-022, TC-024, TC-025, TC-026, TC-029 |
| **MVP-AC-12** | **12. Streaming works.** | - Authorized website calls `ai.chat.completions.create({ model, messages, stream: true })` and iterates with `for await (const chunk of stream)`.<br>- Incremental `ChatCompletionChunk` objects arrive in sequence order, starting with `delta.role = "assistant"` and ending with a terminal `finish_reason`.<br>- Chunks are delivered exclusively to the originating port. | FR-045, FR-075 | TC-023, TC-029 |
| **MVP-AC-13** | **13. Generation can be cancelled.** | - Clicking **Stop** in the AI Workspace or triggering `AbortSignal` / `break` in the SDK halts token generation within ≤ 500 ms p95 on RC-1 – RC-3.<br>- Runtime transitions cleanly to `idle` (or processes the next queued request).<br>- A client cannot cancel a request belonging to another port/origin. | FR-034, FR-046, FR-076, NFR-004 | TC-011, TC-040 |
| **MVP-AC-14** | **14. Unauthorized websites are rejected.** | - 100% of connection or API requests from origins without an active grant are rejected with `permission_required`, `permission_denied`, or `origin_not_allowed`.<br>- Unauthorized requests never start the Runtime Host or expose installed model lists.<br>- Spoofed origins in message payloads, mismatched schemes/ports, and unauthorized iframes inside authorized pages are rejected 100% of the time. | FR-065, FR-068, FR-111, FR-115, BR-03, BR-04, NFR-014 | TC-027, TC-028, TC-031 |
| **MVP-AC-15** | **15. User can revoke an authorized website.** | - User clicks **Revoke** on an authorized origin in Website Integrations (or removes permission in browser settings).<br>- Active ports for that origin disconnect immediately, any in-flight generation is cancelled with `permission_revoked` within 1 s, the content script is unregistered, and the browser host permission is removed.<br>- 100% of subsequent requests from that origin are rejected. | FR-064, FR-112, BR-06 | TC-030 |
| **MVP-AC-16** | **16. Runtime failures produce understandable error messages.** | - Every failure mode (unsupported WebGPU, insufficient storage/VRAM, corrupted model, context length exceeded, rate limit, queue full, worker crash / device lost) returns a structured `UOAIError` code from the error catalogue and displays a plain-language UI message with a recovery action (no raw stack traces shown by default).<br>- After an induced worker crash or `device.lost`, the runtime automatically recovers on the next request in ≥ 95% of trials. | FR-037, FR-043, FR-048, FR-049, FR-079, NFR-024, NFR-044, NFR-045 | TC-019, TC-020, TC-032, TC-036, TC-041 |
| **MVP-AC-17** | **17. No prompt is transmitted to a cloud inference provider.** | - Network packet capture and Playwright network interception during onboarding, workspace chat, website SDK requests, and induced runtime failure confirm 0 bytes of prompt, message, or generated response content are ever sent to any external host.<br>- Canary-string audit confirms 0 occurrences of prompt/response content in local diagnostic logs, exported diagnostics JSON, or any analytics payload. | FR-105, FR-110, FR-113, FR-114, FR-124, BR-01, BR-02, BR-05, BR-21, NFR-012, NFR-020, NFR-021 | TC-033, TC-034, TC-035 |
