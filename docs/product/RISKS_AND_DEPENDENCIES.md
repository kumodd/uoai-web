## 1. Risk Scoring Methodology

- **Probability:** *Low* (unlikely in normal conditions), *Medium* (plausible; occurs on subset of devices/users), *High* (expected challenge given browser platform constraints).
- **Impact:** *Low* (minor UX inconvenience), *Medium* (degrades feature or delays a phase), *High* (blocks core offline/local inference value proposition), *Critical* (security breach, privacy leak, legal violation, or store ban).
- **Severity:** Derived from Probability × Impact (`Low`, `Medium`, `High`, `Critical`).

## 2. Risk Register (R-01 – R-16)

| Risk ID | Area | Description | Prob. | Impact | Severity | Mitigation Plan | Contingency Plan | Owner |
|---|---|---|---|---|---|---|---|---|
| **R-01** | WebGPU Support | WebGPU availability, adapter limits (`maxBufferSize`, `maxStorageBufferBindingSize`), and `shader-f16` support vary across OSs, GPUs, drivers, and Chromium versions. | High | High | **High** | Run worker-level WebGPU capability detection during onboarding (FR-003); qualify models with explicit hardware minimums (FR-012); publish tested browser/hardware matrix (NFR-037). | Provide honest troubleshooting guidance (UC-11); qualify a smaller quantized model for lower-limit GPUs; evaluate optional WASM/CPU fallback for tiny models (OQ-07). | Architecture Lead |
| **R-02** | Browser Compatibility | Chromium derivatives (Chrome, Edge, Brave, Opera, Vivaldi) differ in Offscreen Documents API, WebGPU flags, and storage quota behavior. | Medium | Medium | **Medium** | Target Chrome Stable and Edge Stable as primary supported browsers in MVP (NFR-037); verify required extension APIs dynamically at startup (FR-002). | Clearly label untested Chromium derivatives as "Best Effort" with specific warning badges when an API is missing. | QA Lead |
| **R-03** | Large Model Downloads | Multi-gigabyte model downloads (1 GB – 3+ GB) may fail or stall on slow/unreliable networks or when users close their laptop mid-download. | High | Medium | **High** | Implement chunked staging in OPFS/Cache Storage, live progress/ETA (FR-016), HTTP Range pause/resume (FR-017), and persistent download state recovery across restarts (FR-108). | Host/mirror models on CDN supporting HTTP Range requests; offer smaller quantized model tiers in catalog. | Engineering Lead |
| **R-04** | Browser Storage Eviction | Browser storage is never 100% permanently guaranteed; the browser or OS may evict storage under severe disk pressure, or users may clear site data. | Medium | High | **High** | Store models in the `chrome-extension://` origin with `unlimitedStorage` permission and request `navigator.storage.persist()` (FR-106, ADR-006); run fast startup file checks (FR-103). | Detect missing/evicted files immediately at startup, update Offline Readiness to `Not Ready`, and offer one-click repair/re-download when online (UC-13). | Architecture Lead |
| **R-05** | Hardware & VRAM Limitations | Loading a model on devices with shared/integrated GPU memory (8 GB RAM laptops) may trigger WebGPU Out-of-Memory (OOM) or OS GPU driver resets. | High | High | **High** | Enforce pre-load buffer/memory checks (FR-048); default to conservative context lengths (FR-014); enforce single active loaded model (BR-12) and idle auto-unload (BR-20). | Catch OOM and `device.lost` cleanly (FR-040, FR-049), release partial allocations, and prompt user to reduce context length or switch to a smaller model (UC-12). | Architecture Lead |
| **R-06** | Inference Performance | Token generation speed or time-to-first-token (TTFT) on mid-range integrated GPUs may feel slow compared to cloud APIs, or block the UI. | Medium | Medium | **Medium** | Run all inference in a dedicated Web Worker (PC-06, NFR-003); stream tokens immediately (FR-045); perform shader warm-up on load (FR-041); measure on RC-1 – RC-4 (NFR-001, NFR-002). | Allow users to cancel slow generations in ≤ 500 ms (FR-046); set realistic expectations in UI during model selection. | Engineering Lead |
| **R-07** | Extension Lifecycle Limits | MV3 Service Workers terminate when idle; offscreen documents or extension contexts may be terminated by the browser, interrupting state or connections. | High | High | **High** | Never run inference in the SW (PC-06); host the Inference Worker in an offscreen document or pinned extension context (ADR-002); keep durable state in `chrome.storage.local` / IndexedDB; build SDK auto-reconnect (FR-072). | If the Runtime Host is killed mid-generation, emit retryable `runtime_restarted` error and transparently recreate the host on the next request (FR-049, UC-14). | Architecture Lead |
| **R-08** | Model Licensing & Candidate Viability | Candidate model (`Gemma 4 E2B Instruct`) may have license terms requiring specific attribution/acceptance, or its browser-compatible ONNX/WebGPU artifacts may not pass qualification in Phase 0. | Medium | High | **High** | Treat Gemma 4 E2B Instruct strictly as a candidate pending Phase 0 validation (OQ-01); enforce pre-download license display and acceptance (FR-015, BR-19); engage Legal review (SH-12). | Maintain a shortlist of alternative browser-proven open-weights candidates (e.g., Qwen 2.5 / Llama 3.2 / SmolLM2 / Phi-3.5 WebGPU builds) ready for qualification in Phase 0. | Product Owner / Legal |
| **R-09** | Third-Party Integration Security | Malicious websites could attempt unauthorized inference, origin spoofing, prompt flood/DoS, or privilege escalation through the extension bridge. | Medium | Critical | **High** | Two-layer per-origin permission grants (FR-061); derive origin strictly from browser sender metadata (FR-065); dynamic content scripts injected only into authorized origins (FR-067); Zod schema validation (FR-066); rate & queue limits (FR-117). | Immediate one-click permission revocation (FR-064) and "Revoke All Websites" kill-switch in Settings. | Security Lead |
| **R-10** | Browser Store Approval | Chrome Web Store or Edge Add-ons reviewers may reject or delay the extension if permissions look overly broad or if WASM/model loading is mistaken for remotely hosted code. | Medium | High | **High** | Package all JS and WASM code inside the extension bundle (NFR-016); download only inert model data tensors/configs (no remote executable code); avoid `<all_urls>` in required permissions by using optional host permissions per origin (NFR-018). | Prepare a clear reviewer justification document explaining the local AI architecture, `unlimitedStorage`, `offscreen`, and `wasm-unsafe-eval` CSP usage. | Product Owner |
| **R-11** | SDK Adoption & Localhost Misconception | Developers used to Ollama/LM Studio may expect `http://localhost:11434/v1` and fail to integrate if they do not understand extension messaging or how to handle visitors without the extension. | Medium | Medium | **Medium** | Provide an OpenAI-shaped SDK (`@uoai/sdk`) so call sites look familiar (FR-074); provide `UOAI.isAvailable()` and drop-in fallback patterns in docs (FR-071, FR-081); state clearly in docs that no localhost HTTP server exists (KL-05). | Ship copy-pasteable React/vanilla-JS connection banners and a reference demo app in Phase 5. | Product Owner |
| **R-12** | Non-Technical User Onboarding Drop-off | Non-technical users may abandon onboarding during a multi-gigabyte model download or feel confused by hardware compatibility errors. | Medium | Medium | **Medium** | Guided single-recommended-model onboarding (FR-006); clear progress/ETA and background resumability (FR-016, FR-017); usability testing with ≥ 8 non-technical participants (NFR-023). | Offer a lightweight "fast setup" model tier (< 1 GB) alongside standard models if download drop-off exceeds threshold (KPI-02). | Product Owner |
| **R-13** | Model Artifact Supply-Chain Tampering | If an upstream model host or CDN is compromised, tampered weights or tokenizer configs could be served to users. | Low | Critical | **High** | Bundle a curated registry with pinned SHA-256 hashes for every file; verify signed registry updates (OQ-08); block any model that fails streaming SHA-256 verification (FR-018, FR-119, BR-08). | Pin registry to bundled hashes and disable remote catalog updates if signing key/host issue is detected. | Security Lead |
| **R-14** | Upstream Runtime Bugs (Transformers.js / ONNX Runtime Web) | Breaking changes or WebGPU shader compiler bugs in upstream inference libraries could cause wrong outputs or crashes on specific GPU drivers. | Medium | Medium | **Medium** | Pin exact versions of Transformers.js / ONNX Runtime Web and bundle their WASM binaries locally; isolate behind `packages/model-adapters` interface; run golden-output tests per model. | Patch or roll back adapter runtime version independently of the SDK and UI packages. | Engineering Lead |
| **R-15** | Multi-Tab Contention & Queue Starvation | Multiple open tabs from an authorized site (or multiple sites) could saturate the single-generation queue, delaying the user's own Workspace chat. | Medium | Low | **Low** | Enforce global queue max of 5 and per-origin pending max of 2 (BR-10), per-origin rate limit of 30/min (BR-15), and allow user to cancel any queued item from the Provider Dashboard. | Enable first-party Workspace priority queueing over third-party origins (decision OQ-10). | Product Owner |
| **R-16** | Unintended Prompt Data Leakage in Errors or Diagnostics | A developer or support workflow could accidentally log prompt payloads into error messages or exported diagnostics JSON. | Low | Critical | **Medium** | Enforce content-free typed log schemas at compile time (FR-114, NFR-046); run automated canary-string privacy tests in CI on all error paths and diagnostic exports (TC-035). | Block release on any TC-035 canary failure. | Security Lead |
